# 当前 Agent 按需执行技能

## 目标与来源

用户要求 Skill、MCP 和命令使用方式与 Codex 保持一致。采用 [官方技能文档](https://learn.chatgpt.com/docs/build-skills) 中名称/描述先发现、完整 SKILL.md 按需读取、按任务隐式选择、`$技能名` 显式选择。继续支持现有模型渠道，不替换为 Codex 运行时。

## 调用链路

1. AgentExecutor 获取当前 Agent 已授权内置工具、MCP 工具，以及已关联启用的技能。
2. SkillToolFactory 提供三个固定读取工具：skills_list（元数据目录与搜索分页）、skills_read（正文与文件清单）、skills_read_file（包内文件分段读取）。初始目录最多约8,000字符，超出通过分页发现。
3. 模型读取所需技能，工具结果返回同一图循环。当前 Agent 继续执行后续内置/MCP 工具，保留用户任务与系统约束、会话历史、工具事件。不会调用 runBatch 启动 Skill 子 Agent。
4. 手动技能的旧 system_prompt 列继续保存正文；input_schema、enabled_tools、skill_mcp_servers 不删、不迁移、不再用于技能执行。读取技能不能增加宿主权限。原 BatchRunOptions.isSkillExecution 保留旧调用方兼容，仍可限制子任务不注入读取工具。

技能内容是工作流资料，不是替代系统提示词。脚本、模板、引用按需读取，不自动运行脚本，不新增通用服务器 shell。文件只可从当前 Agent 已关联技能包精确取出；拒绝绝对路径、路径穿越，二进制仅说明类型。SKILL.md 可完整读取，其他文本可分段读取。代理工具仍受现有执行超时、迭代预算、会话锁和取消机制约束。

包内 agents/openai.yaml 的 policy.allow_implicit_invocation=false 在目录中透出，要求模型仅在用户显式指定时使用。解析异常则关闭隐式选择。此处与其他自然语言工具选择规则一致，按模型决策执行，不宣称确定性的策略授权控制。

## MCP 与 command

MCP 连接和实际调用保持既有 ToolRegistry 流程：stdio 启动后端进程，SSE/Streamable HTTP 连接远程服务，发现工具后交给模型选择。MCP command 是可执行文件与参数的连接配置，不是聊天框中的任意 shell。`/mcp` 显示关联配置，不伪造运行状态或连通性结果。

## 输入交互

- `/` 展示技能、MCP、新对话命令；`/skills` 和 `$` 展示已关联启用技能，可按名称/描述搜索，方向键/Enter/鼠标/触摸选择；Escape 关闭。
- 选择只把 `$名称` 放进原消息光标处，保留任务文字，技能全文不放入消息，也不自动发送。
- `/mcp` 在输入框上方查看关联配置，不发送模型消息或启动命令。
- `/new` 切到新对话，不删除历史，执行期间禁止切换。
- 关联读取单独取消与报错，不影响普通聊天；切换 Agent 后旧请求不覆盖新数据。
