# 循势行情统一东方财富

> 后续：用户已要求增加降级。当前策略为东财优先、腾讯备用，见 `2026-10-27-market-source-fallback-impl.md`；本文保留当时严格统一来源的实现记录。

日期：2026-10-27。前后端分支均为 `feature/unify-market-source`，包含前序尚未发布的涨幅功能。

## 背景与目标

板块信息及原行情模块使用东方财富，前序涨幅功能因东方财富日线临时断连改用了腾讯。用户要求统一来源，本次将循势的最新报价、筛选日涨幅和距今涨幅改为东方财富，不自动回退到腾讯；已有行业/概念仍为东方财富，B/S 信号继续使用新浪，不改变信号规则。其他应用的既有行情模块未在此次重构范围。

## 实现与口径

- 最新报价使用 `https://push2.eastmoney.com/api/qt/stock/get`，`fltt=2`、`invt=2`，读取 `f43` 最新价、`f57` 代码、`f86` 报价时间、`f170` 当前日涨跌幅。
- 历史使用 `https://push2his.eastmoney.com/api/qt/stock/kline/get`，`klt=101`、`fqt=1`，自筛选日前 45 天起最多 1200 条，读取 `f51` 日期、`f53` 前复权收盘价和 `f59` 当日涨跌幅。
- 历史当日涨幅直接读取所选日期的 `f59`，不拿今天的 `f170` 代替，也不再用舍入后的两天收盘价反算；当前日使用当天有效报价的 `f170`。
- 距今涨幅仍为 `(最新价 / 筛选日前复权收盘价 - 1) × 100%`。源站只支持的目标日与有效最新报价必须同时存在；不借用其他日期，不将缺失填零。
- 今天盘中继续显示待收盘。报价先读取，日线独立读取：历史源失败时仍能展示当天有效的涨跌幅；报价源失败时仍能展示历史 `f59`。数据都标记 `source=eastmoney`，含义是本功能的唯一配置来源；失败不代表已取得有效数据，需结合数值/null 与原因判断。
- 复用按日期/代码的缓存、并发去重、四路全局并发、缺失原因、报价时间校验、SSRF 校验、禁重定向和单请求 8 秒超时。两个源站请求按股票串行执行，保持最多四路在途请求。

## 只读实测与限制

本机及服务器曾成功读取东方财富报价和日线响应（历史日线返回有效 code 与 56 条数据）。随后再次验证发现日线会间歇性被源站断开；Node、curl、Python 均出现过断连，不能据此承诺源站持续可用。

进一步验证 `stock/get` 实时报价可用，新服务能返回当前日真实涨跌幅与 `quoteAsOf`，但日线断连时历史涨幅及累计为 null 并明确提示。此次没有为绕过连接问题引入其他数据源、代理或新增系统依赖。全部线上探测仅 GET，无部署、扫描或观察池写入。
